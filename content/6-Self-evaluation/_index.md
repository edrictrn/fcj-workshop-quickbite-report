During my time in the Workforce Bootcamp – First Cloud AI Journey program at AWS Vietnam, I explored core AWS services and used them to design, build, and deploy **QuickBite**, a full-stack food ordering and restaurant management platform — covering the FastAPI backend, the React + TypeScript frontend, Docker containerization, and a real deployment on AWS (EC2, RDS, S3, CloudFront, CloudWatch). This gave me hands-on practice with cloud architecture decisions I'd only seen in theory before: private-vs-public networking (RDS security groups), HTTPS/mixed-content handling (CloudFront reverse proxy), and cost-conscious resource cleanup.

Throughout the program, I tried to stay disciplined about finishing each stage — local setup, then Docker, then AWS — before moving to the next, and to keep asking questions when a concept (like VPC security groups or CloudFront cache behaviors) wasn't clicking yet rather than guessing.

### Needs Improvement

* Go beyond the core AWS services used in QuickBite (EC2, RDS, S3, CloudFront, CloudWatch) and get hands-on with the broader catalog — IAM policy design, VPC networking, and infrastructure-as-code (CDK/CloudFormation) instead of manual console setup.
* Build the habit of writing tests and documentation alongside the code, rather than mostly after a feature is already working.
* Improve time management across a full project cycle — the AWS deployment phase took longer than planned because networking issues (RDS connectivity, mixed content) weren't anticipated early enough.
* Practice explaining technical decisions more concisely, especially in English, since a lot of AWS documentation and mentor discussion happens in English.
